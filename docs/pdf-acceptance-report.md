# Claros PDF acceptance baseline

**Audit date:** 2026-07-15
**Corpus:** `C:\Users\Chimdumebi\Downloads\claros-pdf-acceptance-corpus\claros-pdf-corpus`
**Scope:** all 20 supplied PDFs (109 pages): 17 selectable-text, 3 image-only scans. No application or parser code was changed, and nothing was deployed.

## Method and pass rule

I ran the upload parser entry point, `parser.parse_pdf_with_diagnostics`, once for every source PDF and timed it around the parser call. I rendered every source page at 1.5x with the returned `prompt_region` (red) and `answer_region` (blue) painted on the original page, then compared the overlay with the underlying worksheet. The 109 rendered overlays and per-run raw results are temporary evidence at `C:\Users\Chimdumebi\AppData\Local\Temp\claros-pdf-acceptance-audit`.

For this baseline, a selectable-text input passes only when its student prompts are correctly identified with stable IDs, legible/read-in-order text, and usable answer regions. Teacher directions, table values, page artifacts, and empty fallback question `0` are not valid student questions. A scan passes honest-failure handling only when it returns `requires_ocr`; OCR is disabled in the current configuration.

## Outcome

**Do not freeze. Recommend targeted fixes.** Only **1/17 selectable-text worksheets (5.9%)** passed the strict usable-worksheet criterion, far below the 90% freeze threshold. The defects are broad but consistent: the current global numbered-line heuristic mistakes tables/procedures/reference packets for questions, and the answer-box heuristic places generic regions based on extracted-line order rather than the visual response area. This is a targeted parser/layout problem, not evidence yet for replacing the underlying PDF text extractor.

There were no crashes or opening failures. The three image-only scans did not return `requires_ocr`; instead each produced an `empty_extraction` fallback question with ID `0`. That is not an acceptable OCR-required result because it creates a non-answerable question record.

## Metrics

Rates are document-level and deliberately strict. “Question detection” requires the expected question/task set and no critical false/duplicate IDs. “Text fidelity” requires readable, correctly bounded prompt text. “Answer regions” requires a visually usable location for every detected student response. “Honest failure handling” is evaluated only on unusable inputs: a non-`ok` status must explicitly surface the actual condition.

## Recommendation

**Make targeted fixes; do not freeze.** The 5.9% selectable-text usability rate fails the 90% freeze rule. The breakdown is not random across unrelated extraction behavior: it consistently follows two repairable failure modes—unscoped global numbered-list detection and visually unaware answer-region inference. The next baseline should specifically confirm that question detection is limited to student prompt blocks, preserves compound labels/unique IDs and page boundaries, suppresses numeric table/procedure artifacts, and returns `requires_ocr` without an ID-0 question for image-only inputs. Re-run this exact corpus after those changes before considering a broader extraction architecture change.

## Remaining uncertainty

The corpus supplies source/structure descriptions but no gold per-question annotation file. Expected task counts above are therefore a manual visual baseline, with intentional exclusion of teacher material and data-table cells per the corpus rules. This uncertainty does not affect the acceptance decision: the observed false questions, duplicate IDs, incorrect page assignment, missing OCR status, and visibly misplaced answer boxes are unambiguous failures.
